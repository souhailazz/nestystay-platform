# NestyStay M1–M5 master requirements matrix

**Certification date:** 2026-09-26  
**Scope:** signed web milestones 1–5, evaluated from the clean release-certification worktrees.  
**Authoritative contract:** `docs/contracts/NestyStay-Signed-Agreement-April-2026.pdf`  
**Allowed status values:** `PASS`, `FAIL`, `MISSING`, `PARTIAL`, `CONFIG_BLOCKED`, `PROVIDER_BLOCKED`, `NOT_APPLICABLE`, `OUT_OF_SIGNED_SCOPE`.

## Interpretation rules

- `PASS` means the current local path was exercised end to end: action → frontend → API → authorization → business rule → persistence/storage → response → UI state → refresh/persistence check.
- `PARTIAL` means a real implementation exists, but a contract surface, lifecycle boundary, staging verification, provider path, or manual acceptance step remains.
- `CONFIG_BLOCKED` means the application path exists but the required deployment configuration or environment is unavailable.
- `PROVIDER_BLOCKED` means the application path exists but an external provider account, callback, or live/test-provider verification is still required.
- The signed agreement names Alibaba eKYC. The later approved product decision in the repository/client correspondence selects Stripe Identity instead. The runtime therefore uses Stripe Identity, while the contract-level Alibaba row remains `PARTIAL` until that provider change is documented as a signed amendment.
- Phase 6 native mobile applications and the dedicated Gate Guard mobile interface are explicitly outside the M1–M5 web release matrix.
